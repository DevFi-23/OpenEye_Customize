# Hàm kích hoạt theo từng layer và quét số 0 của weight × activation, sparse và dense (2026-11-20)

RTL hiện tại (không đổi từ `ae5665f`), CR 2 X 4 Y 3 (2 × 2 cluster, 48 PE), DMA 64 bit, bộ nhớ lý tưởng, 250 MHz.
230 lần chạy, tất cả PASS (50 lần Conv 7×7 của phần C: giá trị đúng, file tham chiếu khác ở ô đệm, như phép quét 18/11).
Profile: `doc/perf/act_wzero_2026-11-20/` (phần A, B), `doc/perf/zero_grid_2026-11-20/` (phần C). Bảng đầy đủ:
`2026-11-20_act_wzero/results.md`. Thay đổi code: móc `OPENEYE_WGHT_ZERO_FRACTION` thêm `OPENEYE_WGHT_ZERO_DENSE=1` để đặt
số 0 cả cho weight của layer Dense (`src/open_eye/DRAM.py`, Python; Conv2D không đổi; `test/test_wght_zero_fraction.py` 8/8).

| phần | model | biến | lần chạy |
|---|---|---|---:|
| A | mạng Bảng 2, weight / input ngẫu nhiên (seed 1) | không hàm, ReLU, Leaky ReLU, SiLU, hard-swish (sau mọi Conv / Dense trừ layer cuối) × sparse / dense | 10 |
| B | MNIST đã huấn luyện (ReLU, ảnh 0); mạng Bảng 2 không hàm | weight bằng 0: 0 / 20 / 40 / 60 / 80 % ở mọi Conv và Dense × sparse / dense | 20 |
| C | từng layer của mạng Bảng 2 chạy riêng | weight bằng 0 × input bằng 0, mỗi trục 0 / 20 / 40 / 60 / 80 % × sparse / dense | 200 |

Trong một mạng chạy trọn chỉ đặt được số 0 của input layer đầu (input các layer sau do chip ghi ngược), nên lưới
weight × activation làm trên từng layer (phần C).

## Kết luận

### A. Hàm kích hoạt (hình `act_delta.png`)

1. **Tính hàm tốn 0 chu kỳ ở cả 4 hàm.** Khối kích hoạt làm việc trong pha ghi ngược, cùng số chu kỳ ở cả 5 cấu hình kể cả
   không hàm (Conv1 / Conv2 / Conv3 / Dense 1568: 3.590 / 1.798 / 454 / 35 chu kỳ trong writeback 3.628 / 1.908 / 564 / 145);
   writeback không đổi.
2. **Chi phí trực tiếp:** ReLU và Leaky ReLU 0. SiLU và hard-swish +32 chu kỳ mỗi layer có bảng (pha `load_act`: bảng 256 ô
   × 8 bit = 2.048 bit = 32 word DMA), ở mọi layer kể cả layer đầu; 4 layer → +128.
3. **End to end trên dense:** không hàm = ReLU = Leaky ReLU = 70.369 chu kỳ; SiLU = hard-swish = 70.497 (+128, +0,18 %).
4. **End to end trên sparse:** có hàm lại nhanh hơn không hàm, vì hàm tạo số 0 cho layer sau bỏ qua: ReLU −3.478 (−4,5 %),
   Leaky ReLU −1.641 (−2,1 %), SiLU −907 (−1,2 %), hard-swish −1.146 (−1,5 %); toàn bộ ở pha tính toán của layer sau.
   Số 0 trong output của Conv 14×14 (input của pool 2): không hàm 7 %, ReLU 76 %, Leaky 33 %, SiLU 23 %, hard-swish 24 %
   (dữ liệu ngẫu nhiên; model đã huấn luyện xem `2026-11-19_activation_cost.md`).
5. Khác với đo 19/11 trên MNIST (Conv1: +32 của `load_act` bị writeback −32 bù): ở đây writeback không đổi ở mọi layer,
   +32 hiện ra cả ở layer đầu. Chưa tìm hiểu vì sao lần đó writeback ngắn đi.

### B. Weight bằng 0 trên cả mạng (hình `phases_wzero.png`)

1. **Nạp weight không đổi theo tỉ lệ weight bằng 0, ở cả hai chế độ và từng layer** (0 → 80 %): MNIST sparse 38.880,
   dense 23.328 chu kỳ; mạng Bảng 2 sparse 18.450, dense 11.070. Dense luôn ít hơn đúng 40 % (hàng 24 weight: 5 word
   sparse, 3 word dense); mỗi weight vẫn chiếm một ô dù bằng 0.
2. **Phần nạp weight thêm của sparse:** MNIST +15.552 chu kỳ (62 µs, 7,9 % tổng sparse ở 0 %), mạng Bảng 2 +7.380 (30 µs,
   9,5 %). Tỉ trọng nạp weight trong tổng: sparse 19,8 → 23,4 % (MNIST) và 23,7 → 28,0 % (Bảng 2), tăng vì tính toán
   giảm; dense 11,5 % và 15,7 %, không đổi.
3. **Tính toán:** dense không đổi; sparse giảm theo weight bằng 0: MNIST 125.651 → 95.712 (−23,8 % ở 80 %), mạng Bảng 2
   42.688 → 30.755 (−28,0 %). Ở cả mạng, đặt weight bằng 0 cũng làm activation của layer sau có nhiều số 0 hơn (MNIST input
   Dense 74 → 97 %), nên phần giảm này gồm cả hai; phần C tách riêng.
4. **Tổng:** mạng Bảng 2 (không hàm): dense nhanh hơn khi weight bằng 0 ≤ 40 % (9,5 % → 2,9 %), sparse nhanh hơn từ 60 %
   (1,9 %, 80 %: 6,9 %). MNIST (ReLU): sparse luôn nhanh hơn, dense chậm hơn 3,4 % (0 %) đến 22,0 % (80 %).

### C. Một layer, lưới weight × activation (hình `grid_ratio.png`)

1. **Nạp weight giống hệt ở cả 25 điểm của mỗi layer, ở cả hai chế độ** (sparse / dense: Conv1 120 / 72, Conv 14×14 và
   Conv 7×7 3.840 / 2.304, Dense 1568 10.560 / 6.336). **Tính toán dense cũng giống hệt ở cả 25 điểm.** Chỉ tính toán
   sparse thay đổi.
2. **Tỉ trọng nạp weight trong layer** (0 % số 0, sparse / dense): Conv1 0,9 / 0,5 %, Conv 14×14 11,7 / 7,4 %, Conv 7×7
   21,9 / 14,2 %, Dense 1568 64,8 / 52,9 %. Phần nạp thêm của sparse chỉ đáng kể ở layer ít tính toán, nhất là Dense.
3. **Ở Conv, weight bằng 0 giúp sparse ngang hoặc hơn input bằng 0.** Conv 14×14: chỉ weight 80 % → tính toán −31 %
   (22.505 → 15.550), chỉ input 80 % → −26 % (16.553), cả hai → −39 % (13.771). Conv1 (ảnh, 1 channel): input bằng 0 đến
   40 % gần như không bớt chu kỳ, weight 80 % bớt 17 %.
4. **Ở layer Dense, sparse không bỏ qua weight bằng 0:** tính toán giống hệt ở mọi mức weight bằng 0 (40.141 / 50.176
   weight bằng 0 ở mức 80 % đã kiểm trong profile), chỉ input bằng 0 làm giảm (−30 % ở 80 %). Testbench gửi weight của
   layer Dense không nén (`raw_wght_i = 1`, `rtl_test_utils.py`), nên weight 0 vẫn được nhân. Cộng với nạp weight chiếm
   65 % layer, Dense 1568 trên sparse luôn chậm hơn dense: 125–136 %.
5. **Vùng sparse thắng (tổng layer, sparse / dense < 100 %):** Conv 14×14 khi weight ≥ 40 %, hoặc input ≥ 40 %, hoặc cả hai
   ≥ 20 %; Conv 7×7 khi weight ≥ 40 % hoặc input ≥ 60 % (hoặc weight 20 % + input 40 %); Conv1 khi weight ≥ 40 % hoặc input
   80 % (hoặc weight 20 % + input 60 %), lợi tối đa 6 %; Dense 1568 không bao giờ.

### Trả lời: nạp weight có tốn nhiều không giữa hai chế độ

- Sparse luôn nạp weight nhiều hơn dense 5/3 lần ở cấu hình này (dense −40 %), **không phụ thuộc số 0 của weight hay
  activation**: số 0 không làm ngắn pha nạp ở chế độ nào.
- Phần thêm đó nhỏ ở Conv có nhiều tính toán (Conv 14×14: +1.536 chu kỳ, 4,9 % của layer dense), lớn ở layer Dense
  (Dense 1568: +4.224 chu kỳ, 35 % của layer dense) và cộng lại 8–10 % tổng mạng.
- Muốn sparse thắng cần đủ số 0 để phần tính toán tiết kiệm bù được phần nạp thêm; ở layer Dense thì không bù được vì
  weight 0 không được bỏ qua. Đây thêm một lý do cho hướng tách Weight / Activation (weight 8 bit cho layer Dense).
