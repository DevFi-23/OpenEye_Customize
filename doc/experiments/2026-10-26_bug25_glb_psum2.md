# 2026-10-26: bug #25 - conv write-back with NUM_GLB_PSUM = 2 (investigated, then fixed)

Sections 1-8: the investigation, without any RTL or repository code change. Section 9: the fix, made the same day with
the user's approval, and its verification. Tools in `2026-10-26_bug25/` (section 8). Platform unless noted: 2 cluster
columns, `CLUSTER_ROWS=2`, `NUM_GLB_WGHT=3`, `NUM_GLB_IACT=1`, `IACT_RAM_CELLS=4`, `TRANS_WORDS=8`, DMA 64 bit, random data,
`OPENEYE_SEED=1`; `NUM_GLB_PSUM` (the "PEs X-axis" of the paper's Table 3) 2, with 4 as the control.

## 1. Summary

With `NUM_GLB_PSUM = 2` every model that chains a convolution into another layer on chip computes wrong (all 8 X = 2 rows
of the Table 3 rerun, `doc/perf/paper_table3_2026-10-24_fix26.md`). The cause is the **convolution write-back** (psum FSM
`SEND_PSUM_TO_IACT` + main FSM `RECEIVE_PSUMS_TO_IACT`), nothing else: the convolution itself, pooling, Dense and the
Dense write-back are right with `NUM_GLB_PSUM = 2` (section 4: with the right image injected after every conv write-back
the paper network computes the right result).

| | Cause | Side |
|---|---|---|
| G1 | `RECEIVE_PSUMS_TO_IACT` transposes `WRITEBACK_WORDS` lanes x `WRITEBACK_WORDS` cycles. Lanes are pixels (the GLBs of one cluster), cycles are channels (filters). `WRITEBACK_WORDS = min(TRANS_WORDS, NUM_GLB_PSUM)` = 2, so a group holds 2 channels of a pixel, while the iact layout of the next layer has groups of 4 channels per pixel (`used_channels` = 4 for 3x3 kernels). The bytes come out as `p0(c0,c1) p1(c0,c1) p0(c2,c3) p1(c2,c3)` instead of `p0(c0..c3) p1(c0..c3)` | RTL |
| G2 | the same counter `x_pos` that drops the padding pixels at the end of a row (`x_pos < iact_size_x`) and restarts the row (`iact_x_add_up`) counts **groups**; with 2 groups per pixel it drops and wraps at the wrong place (for a 28-pixel row read as 32, everything after pixel 13 of the row) | RTL (same place) |
| G3 | `fsm_psum_limit` of a convolution that writes back is `ceil(iact_x_add_up * filters * iact_size_y / 4) + 11`: the 4 is the pixels read per cycle (`NUM_GLB_PSUM`), so with 2 the state ends half way and the last rows are never written | Python (`layer_parameters.py`) |

**Correction:** README 8b said the iact check "after Conv2 is right" with X = 2. That check (conv output -> pooling input)
is not done at all: the testbench has no layout for a pooling layer's input and logs "skipping the check". With X = 2
every check that is made fails.

**Python alone cannot fix it** (section 5). **Fix** (proposed in section 6, approved and applied the same day, section 9): in `RECEIVE_PSUMS_TO_IACT` keep the group at
4 channels (one pixel) for any number of lanes, emit only the `WRITEBACK_WORDS` lanes of a group and count only those in
`x_pos`; plus the Python `fsm_psum_limit` with `NUM_GLB_PSUM`. For `NUM_GLB_PSUM = 4` the circuit behaves exactly as today.
Checked by emulation in RTL simulation and by a cycle model (section 6).

## 2. Smallest failing case

`run25.py`, `NUM_GLB_PSUM` 2 vs 4:

| Model | `NUM_GLB_PSUM = 4` | `NUM_GLB_PSUM = 2` |
|---|---|---|
| `Convolution_Single` 8x4x4 -> 4 (read out directly, no write-back) | PASS | **PASS** |
| `Convolution_Stack` 8x4x4 -> 4 -> 4 (conv write-back -> conv) | PASS | FAIL: check after layer 0, final result |
| `Conv_Pool_Conv` 8x4x2 -> 8, max-pool, conv (`MAX_POOLING=1`) | PASS | FAIL: check after layer 1, final result |
| `PAPER_MNIST` (Table 3, CR 2 Y 3) | PASS | FAIL: checks after layers 1, 3, 4, 5 (and, with the pooling-input check of section 3, after 0 and 2) |

So the convolution computes and reads out right with two lanes; the write-back is wrong. `Convolution_Stack`, first word
of the buffer (bytes low to high, 2-byte groups):

```
reference  01 fa | fa f6 | 20 1f | 05 f2    = pixel 0 (c0..c3), pixel 1 (c0..c3)
DUT        01 fa | 20 1f | fa f6 | 05 f2    = p0(c0,c1) p1(c0,c1) p0(c2,c3) p1(c2,c3)
```

Every word shows the middle groups swapped (G1); the last words of the image are garbage (G3).

## 3. A check for the input of a pooling layer

`B25_POOLCHECK=4` compares the buffer after a conv layer whose next layer is a pooling layer with the conv layout of the
next layer's input (`IactStreamMapper.build_iact_buffer_words` with `used_channels = 4`). With `NUM_GLB_PSUM = 4` it passes
(`Conv_Pool_Conv`, and all 6 checks of the paper network), so it is the layout the pooling layer reads. With
`NUM_GLB_PSUM = 2` it fails after layers 0 and 2 of the paper network as well.

## 4. The write-back is the only blocker

`B26_INJECT=1` + `B25_POOLCHECK=4`, `NUM_GLB_PSUM = 2`: after every failed check the expected image is written into the
buffer and the model runs on.

| Model | Injected after | Other checks | Final result |
|---|---|---|---|
| `Convolution_Stack` | layer 0 | - | **right** |
| `Conv_Pool_Conv` | layer 0 (conv -> pool) | after layer 1 (pool -> conv): **PASS** | **right** |
| `PAPER_MNIST` CR 2 Y 3 | layers 0, 2 (conv -> pool), 4 (conv -> Dense) | after 1, 3 (pool -> conv) and 5 (Dense -> Dense): **PASS** | **right** |

Pooling, both Dense layers, the Dense write-back (bug #26 fix) and every convolution compute right with two lanes.

## 5. Python alone: no

* **Groups of 2 channels for the next layer** (`B25_UC=2`: `used_channels` capped at 2, so that the layout would match
  G1): a single convolution with 4 or 16 input channels, loaded over DMA, already computes wrong with it (with
  `NUM_GLB_PSUM` 4 and 2 alike). Multiple 2-channel groups are not a working mapping today (a 2-channel input, one group,
  works: MNIST conv1 padded).
* The order of the bytes cannot be changed by the read loops: consecutive groups always come from different lanes
  (different GLBs = different pixels), while the layout needs two consecutive groups of the same pixel. Dropping every
  other group would need `x_pos` to restart every group, i.e. a different `iact_x_add_up`, which the conv iact converter
  uses.
* G3 alone is Python (section 6).

## 6. Proposed fix and how it was checked

**RTL** (`hdl/OpenEye_FPGA.v`, `RECEIVE_PSUMS_TO_IACT`, about 15 lines; the psum FSM side is unchanged):

* `localparam integer WRITEBACK_CHANNELS = 4`: channels of one pixel in the iact layout. The group length (bytes per group,
  cycles per transposition, `iact_to_psum_trans_counter` reload, groups per buffer row `(8/WRITEBACK_CHANNELS) *
  IACT_RAM_CELLS`, slice widths of the shift register and the RAM write bus, the mux depth) uses it instead of
  `WRITEBACK_WORDS`; the number of lanes stays `WRITEBACK_WORDS`.
* A group of the shift register is written in the cycles with `iact_to_psum_trans_counter <= WRITEBACK_WORDS` only (lane
  k in the cycle with counter k+1); in the other cycles of the transposition nothing is shifted and `x_pos` holds (today it
  is reset to 0 in every cycle in which nothing shifts, which only happens before the first group). `x_pos` then counts
  pixels for any lane count, which fixes G2.
* With `WRITEBACK_WORDS = 4` (`NUM_GLB_PSUM = 4`, the configuration of every existing test and of the hardware baseline)
  every condition is true in every cycle: the same circuit as today. Valid for `WRITEBACK_WORDS <= 4`
  (`NUM_GLB_PSUM` 1, 2, 4).

**Python** (`layer_parameters.py`, convolution that writes back): `fsm_psum_limit = ceil(iact_x_add_up * filters *
iact_size_y / W) + 11` with `W = min(TRANS_WORDS, NUM_GLB_PSUM)` instead of 4 (unchanged for W = 4).

**Checked without changing the RTL:**

1. *G3 + G1*, emulated: `B25_LIMIT_W` (the Python limit) plus `B25_UNSWAP` (the DUT bytes regrouped as a 2-lane x
   4-channel transposition writes them): `Convolution_Stack` 16 -> 16 channels 8x8: **128/128 words** right;
   `Conv_Pool_Conv`: 32/32.
2. *G2*, emulated: `B25_XSCALE=2` forces `iact_size_x` and `iact_x_add_up` to twice their value while a conv layer
   writes back (its computation is done), so the group counter drops and wraps at the right pixels:

   | Write-back | without | with `B25_XSCALE=2` |
   |---|---|---|
   | `Convolution_Stack` 14 px wide (read as 16) | 24/56 words | **56/56** |
   | paper L0, conv1 28x28 (read as 32) | 784/1568 | **1568/1568** |
   | paper L2, conv2 14x14 | 336/784 | **784/784** |
   | paper L4, conv3 7x7 (read as 8) | 28/196 | 84/196 (*) |

   (*) An odd width is the limit of this emulation, not of the proposal: with 2-channel groups the padding pixel 7 and
   pixel 6 share a transposition and the group count cuts between `p7(c0,c1)` and `p6(c2,c3)`; with 4-channel groups
   the whole padding pixel is dropped.
3. *Cycle model* (`model25.py`) of today's packer and of the proposal, fed with the read order seen in RTL (per 4 cycles
   the channels c0..c3 of the W pixels of one cluster): today's packer reproduces the swapped bytes of section 2 for
   W = 2 and is right for W = 4; the proposal is right for W = 2 and 4, for row widths 6, 7 (padded to 8), 8, 14 (16), 28
   (32), is cycle for cycle the old circuit for W = 4, and keeps the Dense write-back (lane 0 only) in order.

**Cost:** two lanes read half the pixels per cycle, so the conv write-back takes about twice as long. Paper network
CR 2 X 2 Y 3: conv1 write-back 3,667 -> 7,251 cycles, conv2 1,923 -> 3,715, conv3 571 -> 1,027; the network 131,858 ->
137,636 cycles (+4.4 %). The X = 2 rows of Table 3 measured so far are about 4 % too fast for this reason.

**Not covered:** `NUM_GLB_PSUM = 8` (8 lanes, more than one group can emit in 4 cycles; wrong today too); a next layer
with `used_channels` other than 4 (e.g. a 7x7 conv, `used_channels` = 2) right after a conv write-back: also wrong
today with 4 lanes, the MNIST nets have a pooling layer there; `TRANS_WORDS < NUM_GLB_PSUM` makes `WRITEBACK_WORDS` < 4 as
well (the proposal covers the packer, the psum side then reads only `TRANS_WORDS` of the GLBs).

## 7. History

`WRITEBACK_WORDS` came with `4ed008a` (2026-09-19, Hendrik Woehrle, "Fix convolution write-back cluster stride and active
lanes"), which replaced the earlier packer (modes for 4, 2 and 1 bytes per pixel, from `iact_channels_per_pe_next_layer`)
by the square transposition; that commit was validated with `NUM_GLB_PSUM = 4` only. Upstream head is unchanged here.

## 9. The fix (2026-10-26, approved by the user)

| File | Change |
|---|---|
| `hdl/OpenEye_FPGA.v` | `localparam WRITEBACK_CHANNELS = 4`; in `RECEIVE_PSUMS_TO_IACT` the group length (transposition cycles, `iact_to_psum_trans_counter` reload, groups per buffer row, slice widths of the mux and shift registers and the RAM write bus, storage counter width) uses it, the lane count stays `WRITEBACK_WORDS`; a group is written only in the cycles with `iact_to_psum_trans_counter <= WRITEBACK_WORDS` (compared as 4 bits; or-ed with the constant `WRITEBACK_WORDS >= WRITEBACK_CHANNELS`, so synthesis drops the comparison for 4 lanes) and `x_pos` holds in the others (it is reset only before the first group); the flush uses the same group size |
| `src/open_eye/layer_parameters.py` | `fsm_psum_limit` of a writing-back convolution divides by `min(TRANS_WORDS, NUM_GLB_PSUM)` (the write-back lanes) instead of 4 |
| `src/open_eye/writeback_model.py` (new) | the cycle model of section 6 (read loops + packer with separate lane count and group length), shared by the unit tests |
| `test/test_conv_writeback.py` (new) | 12 tests: pixels in order with 2 and 4 lanes for row widths 6, 7, 8, 14, 28 (read as 8, 8, 8, 16, 32); the old grouping with 2 lanes reproduces the swapped bytes |
| `test/test_fc_writeback.py` | uses the shared model (now with 4-channel groups): the Dense write-back stays in order with 2 and 4 lanes |
| `test/cocotb_fpga/test_glb_psum2.py` (new) | 7 RTL tests with `NUM_GLB_PSUM = 2`: conv (no write-back), conv -> conv (4, 16 channels, 14-pixel rows), conv -> pool -> conv (widths 8 and 6), conv -> pool -> conv -> pool -> conv (16 x 16) |

For `NUM_GLB_PSUM = 4` every new condition is constant true and the circuit is the one before the fix.

New bug found on the way, **#27**: `Conv_Pool_Conv_Pool_Conv` on an 8 x 8 input (the second pooling layer pools 4 x 4 to
2 x 2) fails the check after that pooling layer with `NUM_GLB_PSUM` 4 as well as 2 (the buffer holds -128, the max-pool
start value, and two cells are not written); 16 x 16 passes with both. Not investigated.
