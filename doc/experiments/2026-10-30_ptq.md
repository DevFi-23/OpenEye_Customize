# 2026-10-30: post-training quantization (PTQ) of a trained model for the hardware, steps 1-2 (Python only)

Approved by the user: steps 1-2 of the PTQ direction (README_FI 8d item C), Python only, no RTL change.
Step 1: `src/open_eye/ptq.py` and its unit tests. Step 2: the testbench hook and an RTL test with the trained
MNIST model on real test images. Not in this step: the whole model on RTL (Dense 3136 -> 64 hits bug #29),
bug #12 and the mantissa slice (RTL).

## 1. What the Python flow did before

The values packed into the DMA streams had the right format (weights 8 bit + 4-bit overhead, bias 20 bit, quantizer
entries offset 8 | shift 7 | mantissa 25, status registers), but they were test data, not a quantized model:

| Part | Before (`DRAM.py`, `layer_parameters.py`) | For a trained model |
|---|---|---|
| Conv weights | `floor(127 * w_float)`, no scale kept | the trained MNIST weights (\|w\| <= 0.42) used only +-53 of +-127, floor biased, no multiplier derivable |
| Dense weights | random -64..62 | model ignored |
| Bias | Conv 1, Dense c + 1 | model ignored |
| Input | random -32..30 | no image quantization |
| mant / shift | constants [1, 7] (Conv), [1, 9] (Dense) | unrelated to the model's scales |
| `tflite2model.py` | TFLite Q31 multiplier (31 bit), zero points and bias scale ignored, not used by the testbench | conv1: the 31-bit multiplier masked to the 25-bit field, then 8 bits read by the RTL: M = 1.5e-10 instead of 0.00335, every output 0 |

`gtu.to_twos_complement` does not range-check: a weight outside int8 or a bias outside 20 bits would wrap silently.
The new flow checks every parameter before it is packed (`ptq.check_parameters`).

## 2. Upstream (checked 2026-10-30, `upstream/main` = 93f0e82)

15 commits since e78e5b7 (2026-10-23 .. 10-29): DAG support (DRAMContents and the reference keyed by layer name,
`Residual_Block`), wider address and loop registers (`iact_read_limit_*` 18 bit, psum loops 12/24 bit, regmap and
`psum_pipeline.v`), Verilator again, `iact_stream_constructor.v` restored to before 23be043, multi-channel and sparse
conv weight tiling, fixes for bigger nets. Nothing on quantization: DRAM still uses `floor(127*w)`, random Dense
weights, bias 1 / c + 1, random input; the reference still does not saturate; the quantizer still keeps the low 8
bits. The MNIST notebook passes the `.tflite` path as `MODEL_PATH`, which the testbench opens with
`tf.keras.models.load_model` (Keras only). No PTQ to take over. Their DAG refactor of `DRAM.py` and the testbench
will conflict with this change if it is ever merged (not taken, as before).

## 3. Scheme

From the int8 TFLite model (weights int8 symmetric per channel, int32 bias, activations int8 with zero point -128,
calibrated by TFLite on 100 training images; `doc/demo_notebooks/mnist_tensorflow.ipynb` cell 12):

| | Formula | Why |
|---|---|---|
| input | `x = round(p * 127 / 255)`, scale 1/127 | zero point 0: background 0 is a raw 0 (zero skipping, padding 0 correct) |
| activation scale | `s_sym = s * max(\|-128 - zp\|, \|127 - zp\|) / 127` (ReLU outputs: `s * 255/127`) | same real range with zero point 0 |
| weights | `s_w = max\|w_real\| / 127` per layer, `w = round(w_real / s_w)` | one multiplier per layer: exact with bug #12 |
| bias | `round(b_real / (s_in * s_w))`, `b_real = b_int32 * s_in_tflite * s_w_tflite` | psum units |
| quantizer | `M = s_in * s_w / s_out`, largest shift with `round(M * 2^shift) < 256`, offset 0, `act_min` 0 after a ReLU | 8-bit mantissa (RTL slice), fused ReLU (#30) |
| last layer | raw psums, class = argmax(psum * s_w) | PSUM_SEND_RESULTS |

Choices measured on the 10,000 test images (TFLite 99.23 %):

| Variant | Accuracy | Largest psum | Bit-exact on today's RTL |
|---|---:|---:|---|
| **per-tensor weights (chosen)** | **99.23 %** | 216,908 | yes |
| per-channel weights, own multiplier per filter | 99.25 % | 352,566 | needs bug #12 fixed (RTL) |
| per-channel weights, filter 0's multiplier for all (today's hardware) | 99.21 % | 454,398 | yes, but the other filters use the wrong scale |
| per-tensor + rounding term in the bias (round instead of floor) | 99.22 % (emulator) | | no gain, not used |

Asymmetric activations (TFLite's zero point -128) would need a 32-bit psum and padding with the zero point (RTL)
and lose the zero skipping; see `2026-10-28_int8_clamp.md`.

Quantizer settings of the MNIST model: conv1 mant 151 shift 15, conv2 252/18, conv3 250/18, fc1 202/17, fc2 154/16;
`act_min` 0, 0, 0, 0, -128; bias -5,862 .. 3,325.

## 4. Implementation

| File | Change |
|---|---|
| `src/open_eye/ptq.py` (new) | `read_tflite`, `quantize_tflite(per_channel=False)`, `mant_shift`, `check_parameters`, `quantize_image`, `forward` (the hardware arithmetic: 3x3 'same' conv with padding 0, 2x2 max pooling, Dense, `clamp(floor(mant*psum/2^shift), act_min, 127)`, raw psums of the last layer), `predict`, `load_mnist_test`, `dense_input_order`, `TestbenchModel` (fill the testbench DRAM and layer parameters, check the reference of a layer) |
| `test/cocotb_fpga/OpenEye_FPGA_tb.py` | hook `OPENEYE_PTQ=<tflite>:<image index>[:<first layer>]`: quantizes the model, fills weights, biases, input, `quantize` and `act_min` of N layers from the first one (N = testbench layers; a later first layer gets the model's activation there; a last Dense with fewer outputs takes the first ones), and asserts after `collect_results` that the reference of every layer equals `ptq.forward` |
| `test/test_ptq.py` (new) | 17 unit tests (section 5) |
| `test/cocotb_fpga/test_ptq_mnist.py` (new) | RTL, test images 0 and 1: conv1, conv2, conv3 and fc1's first 10 outputs alone, and the model on chip (MNIST_REAL_RELU: Conv 32, MaxPool, Conv 64, MaxPool, Conv 64, Dense 3136 -> 10 as a probe of fc1) |

The Dense input after a Conv/Pooling layer is in the hardware's order (blocks of 4 channels:
`pos = c%4 + 4*row + 4*X*col + 4*X*Y*floor(c/4)`), not TFLite's NHWC. `dense_input_order` gets the permutation from
`test_utils_main.fill_dram_with_ref` itself (fed with the NHWC index of every value), so the weights follow the
same layout as the testbench reference and the RTL write-back.

## 6. RTL results: three new bugs (#31, #32, #33)

The testbench hook was also extended to start at any layer (`OPENEYE_PTQ=<file>:<image>:<first layer>`: the input of a later
first layer is the model's activation there), so every layer runs alone on real data with its raw psums read out.

| Test (images 0 and 1) | Result |
|---|---|
| conv1 on the image (28x28, padded to 2 channels, 85 % of the pixels 0) | DUT = **bias** at all 25,088 outputs (6,591 differ from numpy: the outputs whose products do not sum to 0) |
| conv2 on pool1's output (14x14x32, 68 % zeros) | DUT = bias at 12,320 of 12,544 outputs, all 12,544 differ |
| conv3 on pool2's output (7x7x64, 73 % zeros) | products right; **DUT - numpy constant per filter, in pairs**: f0 -21 / f1 +21, f2 -81 / f3 +81, f4 -847 / f5 +847 = the bias difference of the pair: the biases of filters 2k and 2k+1 are swapped |
| fc1, first 10 outputs, on conv3's output (78 % zeros) | image 1: all 10 bit-exact; image 0: all 10 differ (-6,372 .. +5,276), not explained by a shift, a pair swap or a dropped block of inputs |
| the model on chip (Conv, Pool, Conv, Pool, Conv, fc1 probe) | fails at the buffer after the first max pooling: the per-channel background value (the output for a blank image) everywhere, i.e. #31 |

* **#31** (products lost on real sparse inputs): the same layers with random data pass (`test_mnist_layers.py`: random and
  trained-weight conv1/2/3), because `DRAMContents` replaces every zero activation by +-1: no layer loaded through the DMA had
  zero runs before. The fused-ReLU tests (`test_int8_clamp.py`, paper network with ReLU) only had zeros written back on chip, and
  scattered. conv3 (7 pixels wide, one x pass) keeps its products with 73 % zeros. Not investigated (mapper or
  `iact_stream_constructor` / PE side).
* **#32** (bias of filter pairs swapped in conv3): every earlier test had bias 1 for all filters (`OPENEYE_BIAS_STEP` was
  never combined with this geometry); conv1 and conv2 return their own bias. Cheap reproduction: conv 7x7x64 -> 64 with random
  data and `OPENEYE_BIAS_STEP`. Not investigated.
* **#33** (Dense 3136 -> 10, image 0): not investigated.

The check of the buffer after a conv layer followed by pooling is skipped by the testbench (no pooling layout), which is why
the chained run reports #31 only after the pooling. Cycle counts with real data are not reported: the results are wrong.

## 7. Limits and next steps

* Whole model on RTL: bugs #31, #32, #33 first; then Dense 3136 -> 64 (bug #29) blocks fc1 (the RTL tests run fc1's first
  10 outputs). fc2 (64 -> 10) after fc1 is the Dense -> Dense write-back of bug #26 (fixed).
* Per-channel weights need bug #12 fixed (RTL); `TestbenchModel.fill` refuses different multipliers per filter.
* ReLU is read from the TFLite output tensor name (`Relu`); the Keras model of the testbench gives the same bound.
* Only 3x3 'same' stride-1 convolutions, 2x2 max pooling and Dense layers in `forward`.
* A front end for a float Keras model with own calibration (no TFLite file) is not written.
