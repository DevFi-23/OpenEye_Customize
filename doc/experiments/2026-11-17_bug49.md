# 2026-11-17: bug #49 (investigation only, no RTL change)

Found by the Table 2 network with ReLU (`PAPER_MNIST_RELU`) on sparse hardware (`2026-11-17_paper_dense_sparse.md`):
CR 2 X 2 Y 3 and Y 4 fail, "iact after L3, L4, L5; result"; every other configuration, the same two without ReLU, and the
dense hardware pass.

Tools (`2026-11-17_bug49/`): `probe49.py` (cocotb module: the unmodified testbench plus dumps of every iact buffer check
with position-coded layouts, and a monitor of the psum ready bits at every collection start), `test_probe49.py` (runs it
on the tree of `PYTHONPATH`, here clean worktrees of `f435068`, so the main tree could be edited meanwhile),
`analyse49.py` (maps wrong bytes to channel / x / y). Output of CR 2 X 2 Y 3: `analyse49_cr2_x2_y3.txt`,
`ready_orig.json`, `ready_trial_fix.json`, trial patch `trial_fix_49.patch`.

## 1. Where: Conv2, not the pooling

* The first failing check is after layer 3 (pooling 14 x 14 x 32 -> 7 x 7 x 32): 9 wrong bytes, all at pooled x = 3,
  y = 0 / 1, off by 1-2 units (0 -> 1 or 2, 5 -> 6, 6 -> 8, 2 -> 1, 3 -> 4, 5 -> 4): no other window of the channel
  explains them, so the pooled inputs were wrong.
* The buffer after Conv2 (dumped at the check after layer 2, decoded with the iact-buffer layout: groups of 4 channels,
  then row, column, channel) holds **20 of 6,272 values wrong, all at x = 7, y = 1 and 3**, in 15 of the 32 channels.
* The testbench did not see it: `compare_iact_storage` returns "no layout known" (pass) when the next layer is a pooling
  layer, so the output of a convolution that feeds a pooling layer is never checked. The error surfaces one layer later.

## 2. Why: the psum collection starts before an odd PE column is ready (bug #28 at CLUSTER_ROWS 2)

`psum_pipeline.v`, `chain_ready_terms`: the ready condition of `CALCULATE_PSUM` loops over GLB pairs and reads only the
even GLB of each pair; the fix of #28 (2026-11-03) added the odd GLB at `CLUSTER_ROWS == 1` only. At CR 2 X 2 every GLB
starts a chain (router_mode bit 2 set on all 8), the odd ones included:

| RTL | Collection starts recorded (Conv1 ... Conv2, until the check after the second pooling) | Starts with a chain-start GLB not ready | Buffer checks / result |
|---|---:|---:|---|
| `f435068` | 300 | **8** (always an odd GLB: 1, 3, 5 or 7; e.g. ready `11111110`) | Conv2 output wrong, L3, L4, L5 and the result FAIL |
| trial patch (scratch worktree): the odd GLB counts too when it starts a chain | 300 | **0** | **every check PASS**, result PASS |

(The probe module ran the network twice in one simulation, the second time with the monitor; both runs agree: on
`f435068` the check after the pooling fails, with the trial patch every check and the result pass.)

When an odd column finishes late, its PE rows hand their psums up out of step (the #28 mechanism: a row starts together
with the row below instead of 3 cycles after it) and one output pixel of that column comes out wrong in many filters. The
compute time of a PE depends on the zeros it skips, so it is data dependent: the ReLU zeros make the columns finish
unevenly; with the random Table 3 data (no ReLU) no start was early enough to matter.

Trial patch (applied only in the scratch worktree):

```verilog
end else if (rr_g*2 + 1 < NUM_GLB_PSUM) begin : gen_pair_ready_cr
  wire not_chain_start_odd = (router_mode_psum[MODE + ROUTER_MODES_PSUM] == 0);
  assign chain_ready_terms[TERM] = (psum_ready_o_reg[GLB] | not_chain_start) &
                                   (psum_ready_o_reg[GLB+1] | not_chain_start_odd);
end else begin : gen_even_ready
```

## 3. Proposal (not applied; needs approval)

1. RTL, `hdl/psum_pipeline.v`: the trial patch, i.e. the #28 condition for every CLUSTER_ROWS, using each GLB's own
   chain-start bit (at CR 1 it is the existing pair AND). A few LUTs; a few cycles where the collection now waits.
2. Testbench, `rtl_test_utils.compare_iact_storage`: check the output of a convolution that feeds a pooling layer with
   the convolution's own layout (byte `((c // 4 * Y + y) * X + x) * 4 + c % 4`, the decoding used here) instead of
   skipping it, so an error is reported at the layer that makes it.
3. Checks after the fix: Table 3 with ReLU 16 / 16 (sparse), the regression, the ready monitor at all 16 configurations
   (0 early starts), Table 3 and baseline cycles, Vivado.
